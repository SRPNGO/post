**星球阁Wiki编写规范**是为指导星球阁Wiki条目的编纂、维护与拓展而编写的说明文档。本文档总结了星球阁Wiki现有条目的典型结构、格式惯例与编写原则，旨在为参与Wiki编辑的成员提供统一参考，确保各条目之间风格一致、互链完整、信息准确。星球阁Wiki目前托管于 oc.srpn.top 的 `wiki/` 目录下，基于 Jekyll 的 Kramdown Markdown 引擎渲染。

## 一、文件命名与存放

### 1.1 文件命名规则

Wiki 条目统一使用 `.md`（Markdown）后缀，文件名遵循以下原则：

- **英文缩写优先**：如条目已有通用缩写代码，直接采用。例如：`SC.md`（星球圈）、`SYUN.md`（团结工会）、`SRAP.md`（星球阁存档计划）。
- **拼音方案**：无通用缩写时，使用核心关键词的拼音或拼音缩写。例如：`qc.md`（青菜）、`huafen.md`（狗头君花粉）、`jiGuang.md`（极光）。
- **英文人名原样保留**：人物英文名直接使用，大小写与实际称呼一致。例如：`E2.md`（Earth-2）、`maugfy.md`、`acu.md`（Acubens-A）。
- **数字与事件日期**：事件条目以日期或编号开头。例如：`0216banned.md`（2026年2月16日主群被封事件）、`122event.md`（1·22事件）、`473wr.md`（473w人）。
- **中文条目用核心词拼音**：如 `secondGroup.md`（二群制度，英文意译）、`transformation.md`（转型运动，英文意译）、`starLife.md`（恒星生命历程）。

> **注意**：Wiki条目间的互链使用根目录相对路径 `/wiki/<文件名>`，**不带 `.md` 后缀**。因此一旦文件名确定，不应随意更改，以免造成断链。

### 1.2 存放路径

所有 Wiki 条目均存放于站点根目录下的 `wiki/` 文件夹内，不建立子目录。条目间的分类关系通过 [wiki_intro](/wiki/wiki_intro) 主页中的分类列表体现。

## 二、YAML Frontmatter 规范

每个 Wiki 条目文件的**开头必须**包含 YAML 前言块，由两行 `---` 包裹。标准格式如下：

```yaml
---
customExtraContent: | # 这个竖线|必须加，保留后续HTML格式
  <p class="center"><a href="./wiki_intro">返回wiki主页</a></p>
title: 条目的中文完整标题
description: 一句话概括本条目的核心内容（建议30—80字）。
---
```

### 2.1 各字段说明

| 字段 | 是否必填 | 说明 |
|------|---------|------|
| `customExtraContent` | **必填** | 渲染在页脚区域的自定义 HTML，用于放置"返回wiki主页"按钮。竖线 `\|` 后 **必须保留空格**，下一行以两个空格缩进。**不得修改或删除此段**。 |
| `title` | **必填** | 条目的中文完整名称。此值将作为浏览器页面标题（`<title>`标签）和页面顶部 `<h1>` 大标题。应与正文第一段加粗的条目标题一致。 |
| `description` | 可选 | 页面摘要，用于 `<meta description>`。建议填写，有助于搜索引擎索引与站内摘要展示。 |
| `author` | 可选 | 填写作者名，会显示在页面标题下方的"作者：xxx"处。AI生成并经Nsakrty审核的条目一般不填此字段，由页脚注释统一说明。 |

> **提醒**：`customExtraContent` 中的 `./wiki_intro` 路径**不需要修改**。Jekyll 渲染时会自动以当前文件所在目录为基准解析。

## 三、正文结构模板

星球阁 Wiki 条目采用**原子化百科风格**，典型结构按以下顺序排列。并非所有条目都需要包含每一部分，请根据条目性质灵活取舍。

### 3.1 标准结构骨架

```
---
customExtraContent: | # 这个竖线|必须加，保留后续HTML格式
  <p class="center"><a href="./wiki_intro">返回wiki主页</a></p>
title: 条目标题
description: 条目简要说明。
---

**条目标题**（又称**别名1**、**别名2**，英文 **English Name**，缩写 **CODE**）是……用一到两段话给出本词条的核心定义与概括，涵盖时间、地点、性质、主要人物、历史意义。

---

## 概述

[若条目较简短，此节可直接用信息表呈现；若为人物/组织/事件类长条目，概述节可与首段定义合并。]

| 项目 | 内容 |
| :--- | :--- |
| 名称 | 完整名称（别名、缩写） |
| 时间 | 发生时间或存续时间范围 |
| 创建者/核心人物 | 主要关联人物 |
| 历史定位 | 一句话评价或定位 |

---

## [一级章节标题]

### [二级子章节标题]

正文内容……引用原文时使用块引用：

> "引用的原始对话或文献原文。"
>
> —— 《文献名称》或发言人

## 相关页面

- [关联条目1](/wiki/xxx)
- [关联条目2](/wiki/yyy)
- [星球阁官网](https://srpn.top)

注：本文由AI经《星球阁存档计划》资料整理而生成，并经过Nsakrty的审核和修改，最后更新于XXXX年X月。内容仅供参考，不代表官方立场，更多详情请参考星球阁官网([srpn.top](https://srpn.top))。
```

### 3.2 各部分详细说明

#### （1）首段定义句

正文**第一句话**必须以加粗的**条目标题**开头，给出完整定义。建议句式：

> **[条目标题]**（又称**[别名1]**、**[别名2]**，英文 **[English Name]**，缩写 **[CODE]**）是……一句话定义，涵盖性质、时间、核心要素与意义。

示例：
- 事件类：`**Dogepro事件**（2022年6月末—7月13日）是星球阁早期历史上一次重要的外部版权交涉事件。`
- 人物类：`**极光**（原名金楠），来自河北，星球阁副阁主（2024年2月上任）、高层BSTN系成员……`
- 概念类：`**恒星生命历程**（亦作**恒星发展历程**、**恒星演化视频**）是星球圈最具标志性的视频类型之一……`

> **互链规则**：首段定义句中的加粗标题是条目**自身定义的自我介绍**，**不要链接自身**。但句中出现的其他专有名词（如组织名、其他人物名）如果有对应 Wiki 页面，应添加互链。

#### （2）水平分隔线 `---`

在首段定义与"概述"节之间、以及"概述"信息表之后、进入正文详细章节之前，通常会插入 `---` 作为视觉分隔。具体使用节奏：首段定义之后加一次，概述信息表之后再加一次是常见模式。

#### （3）概述 / 概况 节

条目第二部分通常是 `## 概述` 或 `## 概况`。内容形式有两种：

- **信息表形式**：用 Markdown 表格列出关键属性。左列是属性名（项目/性质/时间/创建者/规模…），右列是内容。数据量大的条目（人物、数据档案）首选此形式。
- **说明文字形式**：用 1—3 段文字进一步展开说明条目背景、与其他概念的关系、整体结构等。

概述信息表的左对齐语法 `:---` 在星球阁 Wiki 中**非必须**，简单写法 `|---|` 也可。

#### （4）正文详细章节

按时间顺序或逻辑顺序展开。通用标题建议：

- **历史 / 发展历程**：事件、组织、人物、概念的演变时间线
- **背景**：事件发生前的铺垫、条件积累
- **经过 / 过程**：按阶段细分叙述
- **影响 / 评价**：后续影响、各方评价、历史定位
- **代表作品**：创作相关条目
- **人物关系 / 组织关系**：人物类条目
- **数据**：数据类条目

章节层级建议不超过三级：`##`（大节）→ `###`（小节）。避免使用 `####` 及以下，以免页面层级过深。

#### （5）引用块 `>`

引用存档计划中的原始对话、官方历史记载原文时，使用 Markdown 块引用（`>`）。引用的出处可以是：
- 《星球阁相关文字资料》中的官方历史记载
- 成员对话原文（标注发言人）
- 视频描述或平台原文

当引用有多段时，每段前均以 `>` 开头。引用出处另起一行 `>`，以 `> —— ` 开头标注来源。

```markdown
> "引用的多段原文第一段。"
>
> "引用的多段原文第二段。"
>
> —— Nsakrty（2026年7月对话）
```

#### （6）相关页面 节

在正文末尾、页脚注释之前，可选地设置 `## 相关页面` 节，以无序列表形式列出与本条目关联最紧密的 Wiki 条目和外部链接：

```markdown
## 相关页面

- [星球圈](/wiki/SC)
- [画质爆炸](/wiki/HZBZ)
- [转型运动](/wiki/transformation)
- 星球阁官网：[srpn.top](https://srpn.top)
```

> 注意：此节中的链接使用 **`./xxx` 或 `https://`** 格式（以当前文件为基准的相对路径或绝对路径），而正文中的互链统一使用 **`/wiki/xxx` 根相对路径**。二者格式不同，请勿混淆。

#### （7）页脚注释

每个条目的**最后一行**必须是标准的页脚注释段落（注意不要写成 Markdown 标题）：

```
注：本文由AI经《星球阁存档计划》资料整理而生成，并经过Nsakrty的审核和修改，最后更新于XXXX年X月。内容仅供参考，不代表官方立场，更多详情请参考星球阁官网([srpn.top](https://srpn.top))。
```

请根据实际情况更新"最后更新于"的年月。

## 四、Wiki 互链规则

星球阁 Wiki 的核心特色之一是词条间的**交叉索引**。互链的质量直接关系到 Wiki 的使用体验。请严格遵循以下规则。

### 4.1 链接格式

| 目标位置 | 格式 | 示例 |
|---------|------|------|
| 另一个 Wiki 条目 | `/wiki/<文件名>`（无 `.md` 后缀，根相对路径，以 `/` 开头） | `[转型运动](/wiki/transformation)` |
| 本站 docs 目录下的文章 | `/docs/<文件名>`（无后缀） | `[四三〇事件](/docs/430EventXBJ)` |
| 本站其他页面（如首页） | `/index`、`/traffic` 等 | `[返回首页](/index)` |
| 星球阁官网 srpn.top | `https://srpn.top/<path>` | `[星球阁官网](https://srpn.top/srpn/history)` |
| 其他外部网站 | 完整绝对 URL | `[Nsakrty的主页](https://v.douyin.com/...)` |

### 4.2 链接原则

1. **只链接首次出现**：同一专有名词在同一篇文章正文中，仅在它**第一次出现**的位置加链接。后续再次出现保持纯文本，避免满篇皆是链接影响阅读。

2. **长短语优先匹配**：当一个较长短语与其中的子词都可链接时，**优先链接完整长短语**，不重复拆分。例如：
   - 正确：`[星球阁存档计划](/wiki/SRAP)`（整个短语一次性链接）
   - 错误：将"星球阁"与"存档计划"分别拆开链接
   - 正确：`[星球圈低质低俗化](/wiki/XQDHInvasion)`
   - 错误：分别链接"星球圈"和"低质低俗化"

3. **不链接条目的自身主题**：文章开头加粗的主题词是定义本身，不添加链接。例如 `qc.md` 中的 `**青菜**`、`transformation.md` 中的 `**转型运动**`，首段定义处保持纯文本（加粗），不要加链接。

4. **不加链接的位置**：以下位置**严禁**添加互链：
   - YAML frontmatter 内部（包括 title、description、customExtraContent 字段）
   - Markdown 标题行（`#`、`##`、`###` 开头的行）
   - 代码块内（` ``` ` 包裹的内容）
   - "相关页面"节（此节已自带列表式链接，正文里不要让术语"跳过正文"直接跳到相关页面）
   - 页脚注释段落
   - 已有的链接内部（如 `[已有的链接](url)` 里的文字，不能再嵌套方括号链接）
   - HTML 标签内，如 `<a href="...">文字</a>`

5. **只链接已存在的页面**：如果某个术语尚未创建对应 Wiki 页面（如"星零""史小坑""谷神星""昴星阁""星知司"等），**不添加链接**，保持纯文本即可。切勿"先加链接后补页面"，以免产生断链。

### 4.3 链接与加粗的配合

当术语同时处于加粗标记中时，链接方括号**写在加粗标记内部**：

```markdown
正文中首次出现：**[Nsakrty](/wiki/nsakrty)** 发起了……
```

不要写成 `[**Nsakrty**](/wiki/nsakrty)`（链接在外、加粗在内），虽然渲染结果相近，但与现有 Wiki 惯例不一致。

## 五、Markdown 编写注意事项

### 5.1 文本格式

- **加粗**：专有名词、核心术语、重要数据使用 `**` 包裹。例如 `**2026年2月16日**`、`**约75万字**`。不要滥用加粗，正文段落中的普通叙述性文字保持正常。
- **斜体**：星球阁 Wiki 中极少使用。对引言中的强调可使用，但保持克制。
- **删除线**：一般不使用。如需表示事实变化，直接叙述或加脚注。
- **术语别名**：同一概念有多个称呼时，在定义句中以 `（又称**别名1**、**别名2**，英文 **English**，缩写 **CODE**）` 的形式一次性列出。

### 5.2 日期格式

- **具体日期**：写完整，用 `**2026年2月16日**`（加粗首次出现），不要写成 `2026/2/16` 或 `2026-02-16`。
- **日期范围**：可用 `**2022年6月—12月**`（使用长破折号 `—`，不是短横线 `-`）。
- **近似时间**：写 `约2021年12月` 或 `2022年初`、`2023年上半年` 等中文描述。

### 5.3 表格格式

Wiki 中信息表的常用格式：

```markdown
| 项目 | 内容 |
|------|------|
| 名称 | 星球阁存档计划 |
| 建立时间 | 2025年7月9日 |
```

- 左右对齐冒号 `:---` `---:` 非必须，默认居中或左对齐均可。
- 列数不超过 4 列，过多数据建议拆分为多个小表或改用列表。
- 数据对比表（如粉丝数据时间线、前后对比等）表头可使用加粗 `| **时间** | **粉丝数** |`。

### 5.4 列表格式

- **无序项目**：用 `- ` 开头，不要使用 `* ` 或 `+ `，保持统一。
- **有序步骤**：用 `1. ` `2. ` 开头。多层嵌套时按 Tab 缩进。
- **项目内加粗**：`- **项目名称**：说明文字` 是最常见的模式，冒号后跟叙述。

### 5.5 避免的写法

- 不要使用 HTML 标签直接写样式（如 `<font color="red">`、`<br>`），除非是 frontmatter 的 customExtraContent 字段中已有的 `<p>` / `<a>`。

## 七、新增条目流程

如需向 Wiki 中增加新条目，请按以下步骤进行：

1. **确认必要性**：检查该术语是否已在其他条目中被多次提及。如果一个专有名词在 3 篇及以上的现有条目中出现（且目前没有对应页面），则通常值得建立独立条目。
2. **确定文件名**：按本规范第一章的命名规则确定文件名，并在 `wiki/` 目录下创建 `<filename>.md`。
3. **按模板填充**：复制本规范第三章的结构骨架，填入对应内容。至少包括 frontmatter、首段定义、概述、正文几个部分。
4. **添加互链**：扫描正文中的专有名词，按本规范第四章的规则为首次出现的术语添加链接。
5. **反向回链**：在其他已有条目中首次提到这个新术语的位置，添加指向新条目的 `/wiki/<filename>` 链接。
6. **注册到主页**：编辑 [wiki_intro](/wiki/wiki_intro)，在对应分类下以 `[显示文本](./filename)` 的形式加入新条目。
7. **审核校对**：提交给 Nsakrty 或指定审核者进行事实校对后，即可发布。

## 八、条目类型写作要点

不同性质的条目在写作时各有侧重。以下是针对常见条目的快速参考。

### 8.1 人物类（如 qc.md、SY.md、nsakrty.md）

**必备结构**：
- 首段定义：姓名（别名）、籍贯、身份/职位、主要贡献、历史定位
- 概述信息表：地区、性别、类别、入阁时间、最高粉丝数、现任职位等
- 个人经历 / 历史：分阶段叙述入阁前、入阁后、重大事件中的角色
- 代表作品 / 核心贡献：列出代表作、数据指标
- 粉丝数据 / 关键节点表：有数据支撑时附粉丝数时间线表格
- 人物评价：官方简介原文 + 其他成员的引用评价

### 8.2 事件类（如 122event.md、dogeproEvent.md、0216banned.md）

**必备结构**：
- 首段定义：事件名称、时间、核心冲突方、性质、结果、历史影响
- 概述信息表：名称、时间、地点、涉事方、原因、结果、相关条目
- 背景：事件发生前的积累与条件
- 经过：按时间阶段（第一阶段、第二阶段…）分节叙述详细过程
- 结果与影响：直接后果、长期影响
- 各方评价：引用各方发言

### 8.3 组织/制度类（如 SYUN.md、secondGroup.md、SRAP.md）

**必备结构**：
- 首段定义：组织全称、缩写、成立时间、创立者、性质、主要成就/影响
- 概述信息表：名称、成立/存续时间、创立者、核心成员、宗旨/功能定位
- 创立背景 / 制度初衷：为什么建立、解决什么问题
- 发展演变 / 运行机制：结构、阶段、关键节点
- 历史作用 / 评价：贡献、局限、后续影响

### 8.4 概念/现象类（如 HZBZ.md、XKRJ.md、starLife.md）

**必备结构**：
- 首段定义：概念名称、性质/定义、开创者/出现时间、标志性特征、影响
- 概述信息表：性质、核心特征、开创者/起源、代表作品、巅峰期
- 背景 / 产生条件：为什么在此时出现
- 典型特征 / 内容结构：概念的具体表现形式
- 发展演变：兴起→流行→衰落/转型的完整脉络
- 代表作品 / 案例：列举代表性作品及关键数据
- 影响与评价：对星球圈/星球阁的整体影响

### 8.5 议题分析类（如 resistance.md、OrgId.md、AgeStructure.md）

**必备结构**：
- 首段定义：议题名称、分析时间范围、研究对象、核心问题/结论
- 概述：研究方法/视角、数据来源、核心发现
- 分析正文：按论证逻辑或数据维度分节
- 结论：总结性判断或多方观点对比
- 参考资料：列出支撑分析的具体资料来源
